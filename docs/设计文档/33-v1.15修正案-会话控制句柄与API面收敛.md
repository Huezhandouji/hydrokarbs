### D1:`SessionHandle` 接口定形(不可变定位器)

| 面 | 定形 |

**理由**:v1.1 以来会话操作散置在 `HydrokarbsApi` 扁平面——控制三法以**字符串 sessionId 传参**,查询三法返快照,拼成「先查快照拿 id,再拿 id 调控制法」两步走;id 只是字符串,错传/过期在编译期不可查,运行期才以 `Rejected`/`session-not-found` 显形(且异步法要等 future 才显形)。深模块视角(codebase-design):会话的控制与信息面缺一个统一接口——每个调用方都要重复「解析-守卫-委托」形状(§13.4 hub 编排即例)。句柄把这个形状收进一处:5 法承载「定位 + 信息 + 入/出/切」全部会话侧操作,调用方拿到句柄即拿到操作权,字符串 id 只在解析点出现一次。

### D2:裁决一——`info()` 组合式(快照 record 原样保留)

**决策**:`SessionInfo` record 五分量 `(sessionId, modeId, mapId, members, state)` **原样保留**(冻结行不动,★44 BASELINE 的 `SessionInfo` 行零改动);句柄上唯一信息口 `Optional<SessionInfo> info()`(`SessionHandle.java:41`)——**不**把快照分量平铺成句柄方法。

**理由**(用户裁决):**一份不写两处**——快照的字段口径(members 含宽限期成员、无实例时 modeId/mapId 空串、state 四态名)单点住在 record javadoc(`SessionInfo.java:14-17`);若句柄平铺 `modeId()`/`members()` 等,同一份字段口径要在两处冻结清单(★19 的 `HANDLE_FROZEN` 与 ★44 的 BASELINE `SessionInfo` 行族)各自演进,快照加分量 = 两个公共面同时动。组合式另有一得:`info()` 返 `Optional` 天然承载「会话已消亡」态(→ empty),平铺法则每个分量方法都要各自回答消亡语义(返 null?抛?——第三种错误策略)。快照经 `SessionHandleImpl#snapshot` 单点转换(D5),`HydrokarbsApiImpl` 与句柄 Impl 共享同一份(`HydrokarbsApiImpl.java:311` 注:本类不再转快照)。

**否决替代案「句柄平铺快照分量」**:两处口径、两份冻结清单、消亡语义要逐方法回答——冻结面翻倍换不来任何新能力(调用方 `info().orElseThrow()` 一行即得全部分量)。

### D3:裁决二——`leave` 会话域收窄(仅本句柄会话才移出)

**决策**(以现行实签为准,`SessionHandleImpl.java:60-66`):

```java
@Override
public void leave(UUID player, LeaveReason reason) {
    // 会话域守卫(★v1.15/33 号裁决二):玩家现属会话 == 本句柄会话才移出,
    // 否则 no-op;主线程内查后调,无竞态。
    service.sessionOf(player)
            .filter(current -> current.id().equals(id))
            .ifPresent(current -> service.leave(player, reason));
}
```

仅当玩家现属会话 == 本句柄会话才委托 `SessionService#leave`,否则 **no-op**;玩家不在任何会话 = no-op(幂等,D2 既有口径);`reason` 决定离开语义(QUIT = 断线宽限在册 / KICK = 立即移除,§3.2)。**外部迁移代价不作为考量**(用户裁决):旧 `leaveSession(UUID, LeaveReason)` 是「按玩家全局移出」——不问玩家现属哪个会话一律移出;玩家已被外部(另一句柄/宿主编排)迁移到他会话后,持有旧句柄的调用方再调 `leaveSession` 会**跨会话误踢**。新语义把操作域锚定在句柄会话上:句柄是「这个会话」的控制面,不是「这个玩家」的全局控制面(按玩家解析用 `sessionOf`,语义对称)。主线程内查后调(查 `sessionOf` 与调 `leave` 之间无让点),无竞态。

**否决替代案「保留全局移出语义(句柄只当 id 载体)」**:跨会话误伤面;且「句柄会话与操作目标不一致仍生效」违背定位器语义——句柄定位 A 会话,操作却落在 B 会话,误导调用方。

package com.hydrokarbs.api;

public interface SessionHandle {                                        // :31

    /** 本句柄定位的会话 id(纯值,会话消亡后仍可读)。 */
    String sessionId();                                                 // :34

    /** 现取会话快照(「现取不缓存」):会话已消亡 → empty。主线程调用。 */

     *  (消亡/解散中/入场拒绝 → Rejected;已在册 → 幂等重入)。主线程调用。 */
    JoinResult join(UUID player);                                       // :49

     *  才委托,否则 no-op;主线程内查后调,无竞态。主线程调用。 */
    void leave(UUID player, LeaveReason reason);                        // :57

    /** 切换本会话模式——任意线程发起、Impl 回主线程、future 在主线程完成;
     *  会话已消亡 → future 完成 Rejected(MODE_NOT_FOUND);异常经 future、
     *  永不悬挂;null target → future 异常完成。 */
    CompletableFuture<SwitchResult> switchMode(MatchModeSelection target, Handoff payload);   // :66
}

final class SessionHandleImpl implements SessionHandle {               // :29

    private final SessionId id;
    private final SessionService service;
    private final Executor mainExecutor;

    SessionHandleImpl(SessionId id, SessionService service, Executor mainExecutor) {   // :36
        this.id = Objects.requireNonNull(id, "id");
        this.service = Objects.requireNonNull(service, "service");
        this.mainExecutor = Objects.requireNonNull(mainExecutor, "mainExecutor");
    }

    @Override
    public String sessionId() { return id.value(); }                   // :43

    @Override
    public Optional<SessionInfo> info() {
        return service.session(id).map(SessionHandleImpl::snapshot);   // :49 现解析
    }

    @Override
    public JoinResult join(UUID player) {
        return service.join(id, player);   // 引擎裁决原样透传(逻辑原样迁入)  :56
    }

    @Override
    public void leave(UUID player, LeaveReason reason) {
        service.sessionOf(player)                                       // :63 会话域守卫
                .filter(current -> current.id().equals(id))
                .ifPresent(current -> service.leave(player, reason));
    }

    @Override
    public CompletableFuture<SwitchResult> switchMode(MatchModeSelection target, Handoff payload) {   // :69
        Objects.requireNonNull(target, "target");
        CompletableFuture<SwitchResult> future = new CompletableFuture<>();
        mainExecutor.execute(() -> {                                    // 任意线程 → 回主线程
            try {
                Optional<Session> found = service.session(id);
                CompletableFuture<SwitchResult> delegated = found.isEmpty()
                        ? CompletableFuture.completedFuture(new SwitchResult.Rejected(
                                SwitchResult.Reason.MODE_NOT_FOUND, "session " + id.value() + " 不存在"))
                        : service.switchMode(found.get().id(), target, payload);
                delegated.whenComplete((result, err) -> {              // future 主线程完成
                    if (err != null) { future.completeExceptionally(err); }
                    else { future.complete(result); }
                });
            } catch (RuntimeException e) {
                future.completeExceptionally(e);   // 异常经 future,绝不落进执行器
            }
        });
        return future;
    }

    /** 会话 → 快照(★v1.15 起单点居本类):无当前实例 modeId/mapId 空串;
     *  members 含宽限期成员;转换点一次性取值、集合拷贝(7.1 要点 1)。 */
    static SessionInfo snapshot(Session session) {                     // :99
        Optional<MatchModeInstance> current = session.currentInstance();
        String modeId = current.map(MatchModeInstance::modeId).orElse("");
        String mapId = current.map(instance -> instance.view().map().id()).orElse("");
        List<UUID> members = session.roster().all().stream().map(SessionMember::uuid).toList();
        return new SessionInfo(session.id().value(), modeId, mapId, members,
                session.state().name());
    }
}

## 6. 未决与风险(登记,不静默决定)

| # | 问题 | 倾向 |
|---|---|---|
| Q1 | **句柄无判等语义**:`SessionHandle` 未定义 `equals`/`hashCode`(接口无合成行)——两次 `session("s1")` 解析得到两个实例,`==` 恒假;消费方若把句柄当值对象做集合键/去重会踩空 | 接受:句柄是定位器不是值对象(判等锚点 = `sessionId()`,需要判等就比 id);冻结面不加合成方法,消费纪律写入 javadoc(§13.4 随改) |
| Q2 | **「从未存在」与「已消亡」在解析点同形**:两者均 `session(id) = empty`,调用方无法区分 | 接受:对调用方两者操作语义等价(都不可入、不可切);区分是无消费面的信息,引擎侧会话表本就不留墓碑(§3.6) |
| Q3 | **破坏性重编译窗口**:消费过三迁出法或旧 `SessionInfo` 返回形态的旧编译物断编译(`NoSuchMethodError`/`ClassCastException` 族);无版本常量可拦(★v1.14 终结),公告载体 = 本修正案 + ADR + 版本链文档 + maven 坐标 | 接受:当前唯一消费者 examples/TheirPlugin 已随窗口迁移(build 绿实证);与 ★v1.4/★v1.7 破坏窗口同构,第 6 次豁免双轨 |
| Q4 | **句柄可跨会话生命周期持有**:定位器不因消亡而失效,持有过久的句柄后续操作全走失效语义(info empty/leave no-op/join Rejected/switch Rejected)——不持句柄缓存会话状态是消费纪律 | 接受:`info()` 现取即弃,快照才是可持有的值;句柄长期持有可能掩盖「会话已换发」的事实(同 id 重建后旧句柄复能用——id 复用是宿主编排责任,引擎不保证 id 不复用),出现真实误用再裁(候选解 = 句柄带代次,现阶段零消费面不造机制件,同 21-D1 推理形状) |
| Q5 | **`sessions()` 逐会话产句柄的分配开销**:每调一次为全部存活会话各 new 一个 `SessionHandleImpl` | 接受:会话数为个位~十位量级(§3.6 部署拓扑),分配成本可忽略;句柄不可变无状态,不做缓存池(缓存即引入失效面,违「现取不缓存」) |
