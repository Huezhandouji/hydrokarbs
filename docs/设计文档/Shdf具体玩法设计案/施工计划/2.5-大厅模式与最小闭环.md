## 目标

大厅以**宿主自管的主世界区域**身份落地(v2.0):LobbyManager/LobbyVote/ReadyState 普通 Bukkit 代码,零框架组件;加上**开局托管闭环**——开局门判定 → `createSession`/`joinSession`(空转测试模式 idlepad)→ 局间 `switchMode` → 散场引导 → 解散接引回大厅。本阶段的可验证物:

1. 大厅三件:LobbyManager(区域/账本)、LobbyVote(宿主版投票语义)、ReadyState(准备);
2. 托管两件:MatchBootstrap(**开局单闸**,全工程唯一 `createSession` 调用点)、LobbyReturnListener(**散场单闸**,唯一 `subscribeSessionEvents` 订阅点);
3. 地图装配器 ShdfMapAssembler:`games/*/maps/*` 自解析 → `MapDefinition` 三字段 → `registerMap`(先落盘铁律);
4. 两个空转测试模式 idlepad/idlepark(宿主经 `registerMode` 显式注册,零 SPI 清单)+ 一张测试地图 worlds/testmap/;
5. 离线测试:开局单闸/装配器容错/idlepad↔idlepark 100 次切换往复/解散接引;起服 ≥10 次人工闭环。

**★13 验收口径变化**:原「大厅只是模式」的玩法线半段(`LobbyIsJustAModeTest`)随设计变更**撤销**——命题由框架线闸门独扛(禁词表 + 同入口切换测试,已先建);"切换同入口"改在本闭环复测:开局(`SessionRecipe.initialModeId` 首切)、局间续局、`MatchEndReturn` 离场全部只经 `HydrokarbsApi`/`SessionPort#requestSwitch`/`requestDissolve` 同一实现面。新验收命题(开局单闸/散场单闸/装配响亮/大厅零框架依赖)建议后续在 ../../16 §16.2 立号(04 §4.8),本阶段先以测试类落地、不自行占号。

## 施工步骤

路径相对宿主工程 `src/main/`(java 或 resources)。宿主为独立插件(`plugin.yml`:`depend: [Hydrokarbs]`,禁 shade;命令 Brigadier 自有根命令 `/shdf`)。

**新增文件清单**:`ShdfPlugin`(主类)、`lobby/`(LobbyManager/LobbyVote/ReadyState/MatchBootstrap/LobbyReturnListener/LobbyConfig)、`map/`(ShdfMapAssembler/ShdfMapKeys/GameConfigs)、`mode/idle/`(IdlePadFactory/IdleParkFactory)、资源(config.yml、games/rotation.yml、games/idlepad/game.yml + maps/testmap/map.yml、games/idlepark/…、worlds/testmap/ 世界目录由服主/测试资源解出)、测试 6 类。

有序步骤:

1. **ShdfPlugin 骨架**:onEnable 首行 `HydrokarbsApi api = Bukkit.getServicesManager().load(HydrokarbsApi.class)`,`api == null` → SEVERE + `setEnabled(false)` 拒载不崩服(v1.14 口径,无版本对照);随后依次:`registerMode(this, new IdlePadFactory(...))`/`IdleParkFactory`、`ShdfMapAssembler.registerAll`、`registerSessionComponents`(本阶段无全局贡献,留空实现位)、启动 LobbyManager 与 LobbyReturnListener(`subscribeSessionEvents`,onDisable `close()` 句柄 + `unregisterMode`/`unregisterMap`/`unregisterSessionComponents` 反注册三连——兜底在框架,显式反注册是纪律)。
2. **LobbyManager + LobbyConfig**(§4.2):`config.yml` 的 `lobby:` 块(bounds/spawn/vote-seconds/min-players);主线程维护 `present`/`ready` 账本;进出判定 = PlayerMoveEvent 节流(区域contains)+ `/shdf lobby` 命令;退服清理(PlayerQuitEvent)。
3. **LobbyVote**(§4.2 表):候选集 = GameConfigs 扫描产物(`mode@map` 对);多数胜/平局 TieBreak.RANDOM(配置可 FIRST_LISTED)/每人一票可改票/零票 `games/rotation.yml` 兜底;聊天候选行 Adventure ClickEvent 执行 `/shdf vote <n>`(玩家名一律 `Placeholder.unparsed`,§14.10)。**纯宿主状态,零框架类型**。
4. **ReadyState + 开局门**(§4.3):`/shdf ready`;开局门五门(人数/票选/地图/模式/角色——本阶段无角色玩法,第五门留接口);门全过 → `MatchBootstrap.openMatch(voteResult, participants)`。
5. **MatchBootstrap**(§4.3 骨架;开局单闸):`new SessionRecipe(modeId, Optional.of(mapId), List.of(), flowExtras)` → `api.createSession` → 逐人 `api.joinSession`;`JoinResult.Rejected` → 该玩家留大厅 + 提示 `rej.detail()`;join 成功者从大厅账本移除。flowExtras 本阶段(idle 模式)= `List.of(new EmptyArenaComponent.Spec(Duration.ofSeconds(10)))`——空转模式无 EndGate,散场 = 玩家 `/shdf leave`(→ `api.leaveSession(u, LeaveReason.KICK)`)+ 空场收尾解散;`MatchEndReturn` 组件在阶段5(TDM 首个竞技模式)落地,本阶段以其职责的简化形态(命令离场)先行。
6. **LobbyReturnListener**(§4.6 骨架;散场单闸):`Dissolved` → 接引收尾;`MemberLeft` → 传送回大厅 spawn;`ModeSwitchCompleted(to=limbo)` → 记待散信号(WARN 日志,本阶段空转模式不应出现)。
7. **ShdfMapAssembler + GameConfigs**(§4.5):扫描 `games/*/maps/*/map.yml` → 按 `world:` 键去重合并(词料 `AttributeBag.Key.of("shdf.<玩法>", "map", …)` + `MapDefinition.TAGS` 并集;`reset-strategy` 冲突 → 启动 `IllegalStateException` 响亮拒);世界目录 `worlds/<name>/` 未落盘 → 响亮拒(异常文案带绝对路径);`api.registerMap(this, new MapDefinition(worldDir, strategy, bag))`。`game.yml` → GameConfig record(id/session-flow/参数),工厂构造时闭包注入——`build(MatchModeConfig cfg)` 的 cfg 形参忽略(框架 modes/<id>.yml 对宿主模式缺省空 config,不依赖)。
8. **IdlePadFactory/IdleParkFactory**(mode/idle/):`MatchModeProvider` 最小实现——Builder 链:displayName/icon/`mapTags(Set.of("idle"))`/`meta(new MatchModeMeta(false, 1, 200))`(三参,recordsHistory=false;v1.7 无能力标签、v1.13 无 defaultTransition);组件表**空**(不挂 EndGate = 无结束判定,§13.3 精神);id `idlepad`/`idlepark` 互为切换往返对象。
9. **资源件**:config.yml(lobby 块 + display 开关)、games/rotation.yml(`[idlepad@testmap]`)、games/idlepad/game.yml + maps/testmap/map.yml(tags `[idle]`、`reset-strategy: REUSE_DIRTY`)、games/idlepark/…同图引用(testmap 共用,词料各一份——**故意覆盖"多玩法共用世界"装配分支**;reset-strategy 声明一致)、worlds/testmap/ 测试世界目录(随测试资源打包,启动断言存在)。
10. **命令**(`/shdf` 根,Brigadier):`lobby`(传送进大厅)、`vote <n>`、`ready`、`leave`(leaveSession(KICK))、`debug session`(查 api.sessions() 快照)。

## 关键实现要点

- **开局单闸/散场单闸是本阶段的灵魂**:`createSession` 只许出现在 MatchBootstrap,`subscribeSessionEvents` 只许出现在 LobbyReturnListener——ArchUnit/文本扫描测试冻结(对应 04 §4.8 新验收命题①②)。除此之外 `com.shdf.lobby/**` 对 `com.hydrokarbs` 的 import 白名单 = `HydrokarbsApi`/`SessionEventView`/`MapDefinition`/`JoinResult`/`LeaveReason`/`SessionRecipe`(04 §4.8 命题④)。
- **托管时序的铁律**:先 `createSession` 后逐人 `joinSession`;任一 join 被拒不影响会话与其余成员(被拒者留大厅);join 成功者**立即**移出大厅账本(§4.3 步骤 3)——大厅账本与框架名册的同步点只有 join 成功/MemberLeft/Dissolved 三处。
- **两段传送**:框架解散送主世界出生点(hubRelocator),宿主接引送大厅 spawn(§4.6);`leaveSession` 不传送(框架现状)——单人 `/shdf leave` 的回大厅传送由 LobbyReturnListener 的 MemberLeft 分支承担,不是命令自己传。
- **装配器容错三响亮**(§4.5):世界目录未落盘、同图 reset-strategy 冲突、map.yml 解析失败 → 启动响亮抛,不带病注册;缺 `world:` 键/玩法目录无 maps → WARN 跳过(§15.2 铁律 1/2 分工)。
- **idlepad/idlepark 的 mapTags 同为 `[idle]`** 合法(自动挑图按注册序);但本阶段开局一律钉图 `testmap`,不吃占位策略(§4.3 要点)。
- **本阶段不做的**(防范围蔓延):MatchEndReturn 完整组件与 rotation 流程(阶段5,随 TDM)、角色门(阶段3)、闲玩活动(v2.0 暂缓)、投票箱子 GUI(聊天点击已够)、表现层(阶段4 后回接竞技模式)。

## 陷阱与纪律

- §14.21 大厅特判反弹的 v2.0 形态:主世界/大厅字样与任何分支逻辑**不得**出现在 `com.hydrokarbs.**`(框架侧禁词表不变);宿主侧反过来——`lobby/**` 不得 import 框架内部面(白名单见上),两向都不许漏。
- §14.10 玩家可控字符串喂 MiniMessage:投票候选行/已投票提示/被拒提示中玩家名一律 `Placeholder.unparsed`。
- §14.6 任务管理:投票周期是宿主自管节拍(BukkitScheduler `runTaskLater` 计票收票),不是框架 tick——idle 模式零组件,框架节拍不服务大厅;onDisable 取消全部宿主任务。
- 事件订阅句柄 `EventSubscription` 是 AutoCloseable:onDisable 必须 close(框架兜底仍在,显式关闭是纪律)。
- 断线宽限不适用大厅(大厅无会话):玩家退服只清宿主账本(PlayerQuitEvent),与框架名册无关;对局内退服走框架宽限,宿主仅在 MemberLeft/宽限满后接引(§4.6 表)。
- `joinSession` 的 KICK/QUIT 语义:`/shdf leave` 用 `LeaveReason.KICK`(立即移除);QUIT 只有框架 SessionIngestListener 会用,宿主不自调。
