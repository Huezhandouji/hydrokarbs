# 32 · v1.14 修正案:API 版本协商机制退场

> HydroKarbs MiniGame Framework · v1.14 修正案(现行,非历史存档;历史存档 17~31 见各文件)
> 变更指示(非设计章节):本修正案把 **★v1.1-D7「API 版本协商」机制整体退场**落盘为正式修正案(决策记录 [ADR-0020](docs/adr/0020-api-version-negotiation-removal.md))——四处一体:`MiniGameApi.API_VERSION` 常量删除、`MatchModeProvider.requiredApiVersion()` SPI 默认方法删除(SPI 面回到 `id`/`build` 两法)、框架 `onEnable` 版本输出行与 `registerMode` 注册点版本打点行删除、消费方 `onEnable` 首行版本对照检查收敛为**纯 api 在场检查**(`api == null` → SEVERE + `setEnabled(false)`,拒载不崩服语义保留)。用户裁决原话:「在 api 里面写一个表明 api 版本的字段毫无意义」。
> 基线:v1.13。本修正案为 **公共面破坏性变更**:删公共常量 + 删 SPI 公开默认方法 = 跨 jar 破坏(与 ★v1.7 删能力两法同构),经用户裁决不设双轨过渡期(**第 5 次**,同 ★v1.4/★v1.6/★v1.7/★v1.13 先例)。方法面零变化:17 方法签名一字不动,★19 FROZEN 17 行不动;★44 BASELINE 删 2 行(`#API_VERSION:int`、`#requiredApiVersion():int`)合法重录(背书 = 32 号/ADR-0020)。
> 版本口径:设计案版本 v1.13 → **v1.14**;`API_VERSION` 数字轴(1~8)**随常量一并终结,不再升版**——v1.0~v1.13 的版本数字沿革转为纯历史陈述(CONTEXT「历史术语」表),兼容性陈述改由版本链文档(README/AGENTS §3)+ 冻结测试(★19/★44)+ maven 坐标承载。

## 0. 一页摘要

**变更(五条决策,D1~D5;代码与测试已随 v1.14 施工窗口完成,git 实况为准)**:

① **D1 常量退场**:`MiniGameApi` 删 `int API_VERSION = 8` 字段及其 javadoc;类 javadoc 补退场登记。冻结面计数不变(常量不是方法,17 法口径不受影响);★44 BASELINE 删 `com.hydrokarbs.api.MiniGameApi#API_VERSION:int` 一行。

② **D2 SPI 版本声明退场**:`MatchModeProvider` 删 `default int requiredApiVersion()`——SPI 面收敛为 `id()`/`build(cfg)` 两法最小面;★44 BASELINE 删 `#requiredApiVersion():int` 一行。字段退场后该方法声明的版本已无对照面,唯一消费 = 注册日志一行,纯装饰。

③ **D3 打点退场**:`HydrokarbsAssembly#assemble` 删「Hydrokarbs API_VERSION=…」启动日志行;`MiniGameApiImpl#registerMode` 注册日志去版本字段(保留 `id` 行——注册诊断价值保留)。

④ **D4 消费方口径收敛**:消费方 `onEnable` 首行检查收敛为 `api == null` 在场检查(框架插件缺席/加载失败仍是真实场景,拒载不崩服语义保留);版本对照 `< REQUIRED` 分支退场。示例插件 `TheirPlugin` 同步:`REQUIRED_API_VERSION` 常量、`shouldDisable` 静态判定与守卫真值表用例删除;`TheirModeFactory` 的 `requiredApiVersion()` 覆写删除。

⑤ **D5 测试与验收处置**:★19(`MiniGameApiSurfaceTest`)FROZEN 17 行零改动、`apiVersionIsEight` 用例删除;★44(`ApiSurfaceTest`)BASELINE 删 2 行合法重录;`ThirdPartyModeRegistrationTest` ④b「版本协商打点」两用例删除(★41 的 D7 打点增款随退场);`EmptyMatchModeFactoryTest` 版本断言删除;`TheirPluginGuardsTest` ★46 真值表用例删除。验收:**★46 就地废止**(编号不删不重排、废止行不计有效命题,先例 = ★32/★v1.7)、★41/★67 就地注、**新增 ★70**(退场机械自证);计数口径 **69→70 条 = 框架 62→63 + SHDF 扩展线 3 + 联合 1(★32,★v1.7 废止行不计有效命题)+ 宿主线 3**(计数 = ★ 编号跨度,★46 废止行仍占号不计有效命题,同 25 号先例)。

**不动**:`MiniGameApi` 17 方法签名、`MatchModeProvider` 的 `id`/`build` 两法、24 号显式注册四法、25 号桥接、29 号属性袋、30 号二值裁决、31 号回退链;★1~★69 其余条目原样有效、断言零放宽。

## 1. 决策 D1~D5

### D1:`MiniGameApi.API_VERSION` 常量退场

**决策**(以现行实签为准,`src/main/java/com/hydrokarbs/api/MiniGameApi.java`):

| 面 | 处置 |
|---|---|
| 字段 | `int API_VERSION = 8;` 整体删除(含字段 javadoc 的 D7 版本协商与消费方首行检查说明) |
| 类 javadoc | 冻结面句「现 17 方法,API_VERSION = 8」→「现 17 方法」;补「API 版本协商面已退场(★v1.14,32 号)」 |
| 冻结面计数 | 17 法口径不变——常量不是方法,`MiniGameApiSurfaceTest` FROZEN 清单本就不含它;★44 BASELINE 删 1 行 |

**理由**:D7 协商闭环需要三方——消费方自带 `REQUIRED` 常量、API 面暴露 `API_VERSION`、工厂声明 `requiredApiVersion()`——而三方同源(同一框架 jar、同一版本链文档),运行期对照实为自我比较:恰好实现检查的消费方必然刚重编译过(对照恒真),没重编译的旧编译物恰恰是版本检查拦不住的那批(它们引用的旧检查代码读的还是旧常量)。真实破坏性(如 ★v1.13 删快照分量)发生在签名侧,运行期数字不提供任何拦截力;版本轴的真实执行载体一直是冻结测试(★19/★44 只增不改)与修正案流程。故常量在 API 面内部纯属冗余自曝——用户裁决原话「在 api 里面写一个表明 api 版本的字段毫无意义」。兼容性陈述迁往版本链文档(README/AGENTS §3)与 maven 坐标(§6-Q1)。

### D2:`MatchModeProvider.requiredApiVersion()` SPI 方法退场

**决策**(以现行实签为准,`src/main/java/com/hydrokarbs/engine/mode/MatchModeProvider.java`):

| 面 | 处置 |
|---|---|
| 方法 | `default int requiredApiVersion() { return 1; }` 整体删除(含 javadoc) |
| SPI 面 | 收敛为 `String id()` + `MatchMode build(MatchModeConfig cfg)` 两法最小面(注册工厂不是注册成品的语义零变化) |
| 冻结测试 | ★44 BASELINE 删 `#requiredApiVersion():int` 一行,合法重录(背书 = 32 号/ADR-0020) |

**理由**:该方法存在的唯一目的是向 D7 协商供数——D1 删常量后声明值无对照面,唯一消费是 `registerMode` 注册日志的 `requiredApiVersion=N` 字段(D3 一并删除),机制消亡后留壳即留死词汇(违「清除」本意,同 ★v1.13 否决「保留字段恒值」先例)。删默认方法不破既有实现的编译(无人被迫覆写过);覆写过它的第三方(样例 `TheirModeFactory` 曾覆写 5)需重编译——与删公共方法同构,已由本修正案破坏性变更口径覆盖。

### D3:版本打点退场(启动行 + 注册行)

**决策**(以现行实签为准):

| 件 | 处置 |
|---|---|
| `HydrokarbsAssembly#assemble` | 删 `plugin.getLogger().info("Hydrokarbs API_VERSION=" + MiniGameApi.API_VERSION)` 及注释行(装配序号 ①②③… 不受影响——版本行本就不带序号) |
| `MiniGameApiImpl#registerMode` | 注册日志 `id={0}, requiredApiVersion={1}` → `id={0}`(注册点打点保留——id 是归属簿记与查重的诊断入口;版本字段删) |

**理由**:启动版本行与注册版本行是 D7 的观测面,机制退场后两者均成无主数据;注册日志保留 id 行是因为显式注册的归属簿记(★v1.6)与 id 查重诊断仍需要它。

### D4:消费方口径收敛(api 在场检查保留)

**决策**(以现行实签为准,`examples/TheirPlugin`):

| 件 | 处置 |
|---|---|
| `TheirPlugin#onEnable` 首行 | `api == null || api.API_VERSION < REQUIRED_API_VERSION` → `api == null`(SEVERE + `setEnabled(false)` 拒载不崩服语义原样;日志文案去版本语) |
| `REQUIRED_API_VERSION` 常量 / `shouldDisable` 静态判定 | 删除 |
| `TheirModeFactory` | `requiredApiVersion()` 覆写删除 |
| `TheirPluginGuardsTest` | `lowOrMissingApiVersionDisablesPlugin` 真值表用例删除(★46 处置见 §5);类 javadoc 补退场登记 |

**理由**:api 缺席(框架插件未装/加载失败)与版本过低是两类不同故障——前者 ServicesManager `load` 返 null,是部署事故,在场检查必须保留;后者在无版本常量后无判定依据,且其实质(消费了更新面方法)由依赖坐标与文档承载。示例插件是消费纪律的示范面,口径必须与框架侧同步,否则示范错。

### D5:测试处置

**决策**(受改清单 grep 全量核实;**用例删除属冻结面变更,须随本件登记**,AGENTS §4-12):

| 类别 | 件 | 处置 |
|---|---|---|
| 冻结面 | `ApiSurfaceTest`(BASELINE 删 2 行、沿革注补 32 号)、`MiniGameApiSurfaceTest`(`apiVersionIsEight` 删除、javadoc 沿革注改写) | 合法重录/删除(背书 = 32 号/ADR-0020);FROZEN 17 行不动 |
| 用例删除 | `ThirdPartyModeRegistrationTest` ④b 两用例(`requiredApiVersionDefaultsToOne`/`registerModeLogsDeclaredRequiredApiVersion`)、`EmptyMatchModeFactoryTest` 版本断言行、`TheirPluginGuardsTest` ★46 真值表用例 | 随机制退场消亡,登记于本件 |
| 新增 | ★70 机械自证(见 §5) | 首建于 v1.14 施工窗口 |
